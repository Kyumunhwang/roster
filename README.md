   1. 서버 기반 데이터 관리 (server.js):
       - Express.js를 사용하여 HTTP 서버를 구축했습니다. 이제 브라우저는 data/roster.json 파일을 직접 읽는 대신, 서버의
         API(/api/roster)를 통해 데이터를 주고받습니다.
       - 파일 시스템 (fs) 모듈: 서버는 클라이언트로부터 새 데이터를 받으면 기존 JSON 파일을 읽고, 새 항목을 추가한 뒤
         다시 파일에 쓰는 작업을 수행합니다. 이 과정에서 JSON.stringify(..., null, 4)를 사용하여 사람이 읽기 편한 포맷을
         유지합니다.
   2. 데이터 입력 기능 (add.html):
       - 사용자가 폼에 입력한 데이터는 JavaScript의 JSON 객체로 가공됩니다.
       - fetch POST 요청: 브라우저는 이 데이터를 JSON 형식으로 서버에 전송합니다. 성공 시 대시보드로 자동 리다이렉트되어
         즉시 업데이트된 통계를 볼 수 있습니다.
   3. 통합 대시보드 (index.html):
       - 이제 상단에 "+ 새 학생 추가하기" 버튼이 생겼습니다.
       - 서버 API를 통해 데이터를 가져오므로, 새로 추가된 학생 데이터가 실시간으로 차트와 테이블에 반영됩니다.

✦ 사용자 편의성을 고려했을 때, "전체 리스트에서 버튼 하나로 즉시 삭제"하는 방식이 가장 직관적이고 편리합니다. 검색은
  데이터가 수천 건일 때 유용하지만, 현재 150여 건 정도라면 한눈에 보면서 삭제하는 것이 실수를 줄일 수 있습니다.

  따라서 manage.html (데이터 관리 페이지)를 만들어, 모든 학생 리스트를 표 형식으로 보여주고 각 행 끝에 [삭제] 버튼을
  배치하는 방식으로 구현하겠습니다.

  [4단계: 데이터 삭제 기능 구현 전략]

   1. 백엔드 API (server.js):
       - DELETE /api/roster/:name: 특정 이름(또는 인덱스)을 가진 학생을 배열에서 제거하고 파일을 다시 저장하는 API를
         추가합니다.
   2. 데이터 관리 페이지 (manage.html):
       - 모든 학생의 이름, 학년, 구분 등을 리스트로 보여줍니다.
       - 검색창을 상단에 두어, 리스트가 길어져도 필터링할 수 있게 합니다.
       - 각 행에 빨간색 [삭제] 버튼을 추가합니다.

시스템을 실행하려면 터미널에서 다음 명령어를 입력하세요.
node server.js
그 후 브라우저에서 http://localhost:3000으로 접속하시면 됩니다.


✦ 이 오류는 roster.json 파일 안에 JSON 표준이 아닌 NaN (Not a Number)이라는 값이 포함되어 있어 Node.js의 JSON.parse가
  이를 읽지 못해 발생하는 문제입니다.

  파이썬의 pandas 라이브러리는 비어 있는 엑셀 셀을 NaN으로 처리하는데, 이를 JSON으로 저장할 때 null로 변환하지 않고
  그대로 NaN이라고 기록한 것이 원인입니다.

  [해결 방법: 파이썬 변환 스크립트 수정 및 데이터 재생성]

   1. 파이썬 스크립트 수정: 모든 NaN 값을 JSON 표준인 null (파이썬의 None)로 확실하게 변환하도록 코드를 보강하겠습니다.
   2. 데이터 재변환: 수정된 스크립트를 실행하여 올바른 roster.json을 다시 만듭니다.

  먼저 scripts/excel_to_json.py 파일을 수정하겠습니다.



    [4단계 완료 및 기술적 설명]
   1. 동적 리스트 렌더링 (manage.html):
       - 서버로부터 전체 학생 데이터를 가져와 JavaScript로 테이블(<table>)을 동적으로 생성합니다.
       - status_type에 따라 '자퇴'는 빨간색, '휴학'은 파란색 태그를 부여하여 시인성을 높였습니다.
   2. 실시간 필터링 기능:
       - 상단 검색창에 이름을 입력하면 onkeyup 이벤트를 통해 즉시 리스트가 필터링됩니다. 이는 전체 데이터를 메모리에
         들고 있으면서 filter() 메서드를 사용하기 때문에 매우 빠릅니다.
   3. 삭제 API 엔드포인트 (DELETE /api/roster/:name):
       - RESTful API 설계 원칙에 따라 특정 리소스를 삭제하기 위해 DELETE 메서드를 사용했습니다.
       - 서버 측에서는 filter() 메서드를 사용하여 삭제 대상을 제외한 새로운 배열을 만들고, 이를 roster.json에 덮어쓰는
         방식으로 데이터를 영구 삭제합니다.
   4. 사용자 안전 장치:
       - 삭제 버튼 클릭 시 브라우저 기본 confirm() 창을 띄워 사용자가 실수로 데이터를 삭제하는 것을 방지했습니다.
